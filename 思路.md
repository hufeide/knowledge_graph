使用 **多 Agent 架构构建知识图谱（Knowledge Graph, KG）**，核心思想是：让不同 Agent 分工完成 **信息采集 → 信息抽取 → 实体关系识别 → 图谱构建 → 质量校验 → 图谱应用**。

下面给一个比较完整的工程流程，适合你现在的环境（FalkorDB + LLM Agent + 本地模型）。

---

# 多 Agent 知识图谱构建流程

```
                 用户问题 / 文档 / 数据源
                         |
                         v
                 ┌──────────────┐
                 │  数据采集Agent │
                 └──────────────┘
                         |
                         v
                 ┌──────────────┐
                 │ 文本理解Agent │
                 └──────────────┘
                         |
                         v
          ┌──────────────────────────┐
          │       信息抽取Agent       │
          │ Entity + Relation + Event │
          └──────────────────────────┘
                         |
                         v
                 ┌──────────────┐
                 │ 图谱设计Agent │
                 └──────────────┘
                         |
                         v
                 ┌──────────────┐
                 │ 图谱写入Agent │
                 └──────────────┘
                         |
                         v
                 ┌──────────────┐
                 │ 图谱验证Agent │
                 └──────────────┘
                         |
                         v
                   FalkorDB
                 Knowledge Graph
```

# Agent角色设计

## Agent 1：数据采集 Agent

职责：

- 收集数据
- 清洗格式
- 分块

输入：

```
PDF
网页
数据库
聊天记录
代码仓库
```

输出：

```json
{
 "source":"xxx.pdf",
 "chunks":[
   {
    "id":1,
    "text":"..."
   }
 ]
}
```

技术：

- LangChain Loader
- LlamaIndex
- 自定义 crawler

---

# Agent 2：语义理解 Agent

负责理解上下文。

例如输入：

> OpenAI released GPT-4 in March 2023.

理解：

```
事件:
release

主体:
OpenAI

对象:
GPT-4

时间:
2023-03
```

输出：

```json
{
"type":"event",
"summary":
"OpenAI发布GPT-4"
}
```

---

# Agent 3：实体抽取 Agent（Entity Agent）

负责找实体。

例如：

文本：

```
NVIDIA produces RTX 4090 GPU.
```

抽取：

节点：

```
NVIDIA
  type: Company

RTX4090
  type: Product
```

输出：

```json
{
"entities":[
 {
  "name":"NVIDIA",
  "type":"Company"
 },
 {
  "name":"RTX4090",
  "type":"GPU"
 }
]
}
```

---

# Agent 4：关系抽取 Agent

发现边。

例如：

文本：

```
NVIDIA produces RTX4090
```

生成：

```
(NVIDIA)
    |
 PRODUCES
    |
(RTX4090)
```

JSON:

```json
{
"relations":[
{
"source":"NVIDIA",
"target":"RTX4090",
"type":"PRODUCES"
}
]
}
```

---

# Agent 5：Schema设计 Agent

这个很重要。

它决定你的知识图谱结构。

例如自动设计：

节点：

```
Company
Product
Person
Technology
Event
```

关系：

```
CREATES
OWNS
USES
DEPENDS_ON
WORKS_FOR
```

类似：

```
        Company
           |
        CREATES
           |
        Product
           |
        USES
           |
       Technology
```

---

# Agent 6：Graph Builder Agent

负责写入 FalkorDB。

例如：

Cypher:

```cypher
CREATE
(n:NVIDIA:Company
{name:"NVIDIA"})
```

关系：

```cypher
MATCH
(a:Company),
(b:Product)

WHERE
a.name="NVIDIA"
AND
b.name="RTX4090"

CREATE
(a)-[:PRODUCES]->(b)
```

---

# Agent 7：Graph Validator Agent

检查：

## 重复实体

例如：

```
OpenAI
Open AI
openai
```

合并：

```
OpenAI
```

---

## 错误关系

例如：

错误：

```
RTX4090
    WORKS_FOR
    NVIDIA
```

应该：

```
NVIDIA
    PRODUCES
    RTX4090
```

---

## 冲突检测

例如：

来源A：

```
GPT-5 released 2025
```

来源B：

```
GPT-5 released 2026
```

产生：

```
Conflict Node
```

# 多 Agent 协作方式

推荐使用 Supervisor 模式：

```
                 Supervisor Agent

                        |
 ------------------------------------------------
 |              |              |                |
Data Agent  Extract Agent  Graph Agent   QA Agent

                        |
                    FalkorDB
```

Supervisor负责：

- 分配任务
- 判断是否继续
- 重试失败 Agent

